# 机制与代码说明

核心业务约束：同一场所的重叠时段最多批准一份。待审核申请可以重叠。源码路径统一为 `src/main/java/edu/baodex/campus`；以下行号对应正式交付源码。

## 1. 线性一致性：已经完成的操作对后续请求生效

现象：批准A已返回成功，随后才发起的查询却看到批准前的日程，后续取消或判断便可能依据旧状态。这里讨论服务端请求，不把页面未刷新当作一致性故障。

`KvGateway.java` 20–38：`get()` 与 `scan()` 通过 `send()` 包装为命令，使用 `client.io().send(...)` 进入普通复制日志路径。`KvMachine.java` 79–90：有序提交后的命令交给 `state.apply()`。读取因此服从已提交操作的顺序。代价是读取也增加日志与复制开销。

删去 `return send(...)` 本身会使方法无法正常工作。若把这条路径改为直接返回本地副本或旧缓存，就可能读到落后状态。诊断接口的本地观察值不等同于核心业务读取。

线性一致的单次读写不自动把“读取—检查—更新”三个步骤变为一个事务：两个并发请求可以都合法地读到v7，仍需提交时的版本条件。

## 2. CAS 与原子更新：保护业务判断的依据

现象：A申请14–16点，B申请15–17点；两个管理员都读到v7并检查通过。如果直接把修改后的整份日程写回，会产生旧快照覆盖和丢失更新。

`DistributedApi.java` 295：批准前 `checkOverlap(rows,start,end)` 检查已批准占用。344–350行定义重叠：已有开始小于本次结束，并且已有结束大于本次开始。区间首尾相接允许共存。

315–337行把读取版本放进 `expected`，把更新放进 `BATCH`。`KvState.java` 58–71先遍历并检查所有版本，任何条件不满足返回 `VERSION_CONFLICT`；全部通过后才整体递增版本、写入值。业务接口遇冲突重读并重新判断。A把v7改成v8，B携带v7就不能直接提交。

删除重叠检查：CAS仍能正常比较版本，但顺序审批也可能批准两份重叠预约。删除61–62行版本检查：旧判断可能覆盖更新后的日程。仅有其中一层不能替代另一层。

## 3. 幂等：重复请求返回第一次结果

现象：申请已经创建预约，正常响应没到达客户端；用户看到超时后重发同一操作。超时不等于没有执行。

`DistributedApi.java` 210–223：用户ID与 `X-Request-ID` 标识一次操作；摘要绑定操作、目标、用户和请求体；入口先查 `RESULT`。`KvState.java` 39–44是最终去重：ID已出现且摘要相同就返回原结果；摘要不同返回 `REQUEST_ID_REUSED`。72–74行保存摘要和结果。

日程变更与结果在同次状态机应用中保存。80–98行快照导出、导入同时包含值、版本、请求表；`KvMachine.java` 保存快照并恢复后重放日志。因此重启后仍能识别完成过的请求。

只删除入口 `RESULT` 查询，状态机还有最终保护。若绕过状态机去重并丢失结果记录，重复申请可能再次执行；若只在内存去重，重启后可能失去记忆。同内容使用新请求ID被视为新操作，不会自动按文字相同合并。

## 4. 多副本共识：确认同一组提交命令及顺序

现象：网络分开后，如果节点各自确认资源占用，即使每台都有CAS，也可能基于各自历史批准冲突预约。

`KvCluster.java` 20–24固定n0、n1、n2；43–62配置独立日志目录、同步落盘，并把 `group()` 与 `KvMachine` 绑定给Ratis。多数派2/3提交、选主及日志复制由Apache Ratis实现；项目没有另写一个计数条件替代Raft。

`KvMachine.java` 79–90取得提交日志中的命令，调用 `state.apply()` 完成版本、原子批处理与去重，再记录应用位置。共识决定执行顺序，业务检查定义合法占用。

主进程故障后，另外两节点可重新选主；分区成2+1时，多数派一侧可继续提交，孤立侧不能独自确认核心操作。缺少多数派时拒绝或超时，客户端保留请求ID确认结果。写入成功不代表所有副本已经追平。

直接删除复制组或状态机配置会破坏启动或功能，不等于可控地把多数派改成1。若改成收到请求就各自执行本地 `state.apply()`，绕过Raft，便失去跨副本统一顺序。

## 项目范围

分布式模式覆盖申请、审批、驳回、取消与日程查询。账号使用H2；完整费用、使用登记和停用流程保留在基础模块，本次KV核心不承诺覆盖这些流程。`Api.java` 的数据库入口在distributed配置下不启用，保留用于基础模块与现有测试。

按场所与日期聚合让原子检查直接，但热门日程竞争集中；核心读取复制提交提高实现清晰度，也增加日志开销。当前为一个固定复制组，未完成热点分片和在线成员变更。
